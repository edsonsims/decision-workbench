# public-v1: three local model runs

Three actual local models classified the same frozen **130 public examples**: 80 BANKING77 queries across eight intents and 50 CUAD excerpts across five clause types. Each class has ten examples. Source texts, questions and options were frozen before these runs; the [dataset guide](../../docs/datasets.md) explains selection, attribution and limitations.

## Recorded results

The table below is generated by `workbench.benchmark_report` from the saved predictions. Metrics use the original option order. “Reversed choices changed” counts label changes after reversing the same options, among pairs where both calls completed.

| Model | Task | Correct | Macro F1 | Completed | Reversed choices changed | Median call (ms) |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| decisiontune-1.0 | banking_card_intent | 57/80 | 0.689 | 80/80 | 11/80 | 69.2 |
| decisiontune-1.0 | cuad_clause_type | 32/50 | 0.668 | 50/50 | 4/50 | 83.7 |
| laya-multilingual-mlx | banking_card_intent | 53/80 | 0.647 | 80/80 | 27/80 | 56.1 |
| laya-multilingual-mlx | cuad_clause_type | 35/50 | 0.693 | 50/50 | 10/50 | 67.2 |
| qwen3-0.6b-token-scoring | banking_card_intent | 12/80 | 0.071 | 80/80 | 64/80 | 361.8 |
| qwen3-0.6b-token-scoring | cuad_clause_type | 12/50 | 0.137 | 50/50 | 41/50 | 355.2 |

Every run retained all 130 cases and attempted both original and reversed option orders: **780 measured decisions** across three models, plus **three separate warmup calls**, one per model. These runs had **zero provider failures**. Every misclassification remains in `predictions.jsonl`; no errors or cases were dropped to improve the denominator. Completion means a valid supplied label was returned, not that the label was correct. Macro F1 averages the fixed task labels with zero divisions scored as zero.

Original-order accuracy and descriptive 95% percentile bootstrap intervals:

| Model | BANKING77 accuracy, 95% interval | CUAD accuracy, 95% interval |
| --- | ---: | ---: |
| decisiontune-1.0 | 71.25% (61.25–81.25%) | 64.00% (51.02–76.60%) |
| laya-multilingual-mlx | 66.25% (56.25–76.25%) | 70.00% (58.06–82.23%) |
| qwen3-0.6b-token-scoring | 15.00% (7.50–22.50%) | 24.00% (12.24–36.96%) |

Intervals use 2,000 resamples and seed 42. CUAD resamples its **34 source contracts**, preserving excerpts from the same contract together; BANKING77 uses 80 source query IDs. These small, balanced convenience slices do not establish population coverage or model superiority. The comparison does not include a paired test of differences between models.

## What this run suggests

DecisionTune scored more banking queries correctly than Laya, while Laya scored more CUAD excerpts correctly. The differences are small relative to the uncertainty shown above. Laya had lower median call times, but higher p95 times: 155.0 versus 122.1 ms for banking, and 156.4 versus 123.2 ms for CUAD. Both models changed choices when the options were reversed; an encoder decision head does not make option order irrelevant.

The Qwen result concerns this specific **single-token candidate-letter scoring adapter**: no generated answer and no thinking tokens. It performed poorly and changed many labels after reversal. Reversed-order correctness rose from 12 to 18 banking cases and from 12 to 22 CUAD cases, which makes this adapter's position sensitivity a concrete study finding. It does not establish how Qwen performs with other prompts, answer-generation methods, calibration, or fine-tuning. Its weak result is retained; the prompt was not repaired after inspecting these test outputs. Reversal is one diagnostic perturbation, not a revised result chosen in place of the original order.

**Training exposure matters:** BANKING77 is an explicitly disclosed DecisionTune 1.0 fine-tuning source. CUAD is not in its declared fine-tuning list, but earlier exposure is not ruled out. Dataset overlap for the other checkpoints is unknown. None of these results is claimed to be training-unseen. Model option scores have different meanings across adapters and are not calibrated correctness confidence.

These tasks classify supplied excerpts and support queries. They do not evaluate full-contract extraction, all 77 banking intents, out-of-scope rejection, invoice arithmetic, the multi-role review graph, or decisions about legal rights or payments.

Two cases show why the saved predictions matter:

- CUAD `4cda6d5702ddb5427a128aa3` limits assignment of a license without written consent; its source label is `anti_assignment`. DecisionTune changed from the incorrect `audit_rights` to `anti_assignment` after reversal. Laya was correct both times; Qwen changed from correct to `termination_for_convenience`.
- BANKING77 `e1ef76d74eaa9b87f5b8e19c` asks about an unrecognized account payment. DecisionTune was correct both times. Laya changed from `pending_card_payment` to the correct `card_payment_not_recognised`; Qwen changed between two incorrect labels, `pending_card_payment` and `card_delivery_estimate`.

The complete IDs, source text and labels are in the [frozen cases](../../benchmarks/public-v1/cases.jsonl). A choice flip can help, harm, or leave a case incorrect; its count alone is not an accuracy measure.

## Runtime and provenance

The runs used **Apple M4 Max, 64 GiB unified memory, macOS 26.6.2, Python 3.13.1**, on arm64. DecisionTune used MLX; Laya used its FP16 MLX runtime; Qwen used PyTorch FP16 on MPS with four CPU threads. The pinned environment includes MLX 0.32.4, laya-mlx 0.3.0, decision-tune 1.0.0, PyTorch 2.14.1 and Transformers 5.20.1.

Call times are sequential host wall time around `choose()` and returned-decision validation. They include adapter preparation/inference work, exclude model loading and the one warmup, and do not measure HTTP, throughput, memory peaks or another device. Models use different runtimes and input encodings, so this compares **checkpoint plus adapter plus runtime**. Loading/warmup times are preserved separately in each run's provenance.

All three runs executed clean source commit **`3ac608973fe23d9e40b124f7d98a66394edf88a3`**. Their `provenance.sourceFilesSha256` records all eleven Python source hashes, and `lockFilesSha256` binds the dependency locks. Execution completed on 2026-10-18 UTC. A later documentation commit does not change that recorded execution commit.

Every call records the ordered request hash. Laya and Qwen additionally record hashes of their rendered and encoded model inputs. DecisionTune's `inputEncoding` is null: its request hash does not establish the exact encoded token sequence.

## Recompute the report without weights

From the repository root, after installing the core environment:

```sh
python -m workbench.datasets verify
python -m workbench.benchmark_report --runs reference/public-v1
```

This verifies the frozen dataset, case identities, labels, input hashes and option order; validates saved decisions; and recomputes metrics and intervals from every saved prediction. It performs no model loading, download or inference. It checks artifact consistency, not independent attestation of the recorded execution.

## Run the models again on Apple silicon

Use a fresh Python 3.13 environment from the repository root. The lock targets the recorded macOS model environment; other devices or package versions need separate results.

```sh
python3.13 -m venv .local/public-eval-venv
. .local/public-eval-venv/bin/activate
python -m pip install -r requirements-model-macos.lock
export HF_HUB_DISABLE_TELEMETRY=1
export LANGSMITH_TRACING=false
export LANGCHAIN_TRACING_V2=false
```

The following commands explicitly download only pinned public model files, without an authentication token. Loading a backend later uses its local path and does not download weights.

```sh
DECISIONTUNE_MODEL=$(python - <<'PYMODEL'
from huggingface_hub import snapshot_download
print(snapshot_download(
    "decision-tune/decisiontune-1.0",
    revision="27056cb08bcf2b3ba1fd9bccb782b4dfd0498e1f",
    cache_dir=".local/model-cache", token=False,
    allow_patterns=["manifest.json", "config.json", "model.safetensors",
                    "head.safetensors", "tokenizer.json"],
))
PYMODEL
)
LAYA_MODEL=$(python -m workbench.comparison_models download \
  --backend laya-multilingual --cache .local/model-cache)
QWEN_MODEL=$(python -m workbench.comparison_models download \
  --backend qwen3-0.6b --cache .local/model-cache)
```

Run each comparison into a **fresh empty output directory**. These example paths deliberately differ from the published reference; the runner refuses to overwrite earlier runs.

```sh
python -m workbench.benchmark --backend decisiontune \
  --model-path "$DECISIONTUNE_MODEL" --out .local/public-v1-rerun/decisiontune
python -m workbench.benchmark --backend laya-multilingual \
  --model-path "$LAYA_MODEL" --out .local/public-v1-rerun/laya-multilingual
python -m workbench.benchmark --backend qwen3-0.6b \
  --model-path "$QWEN_MODEL" --out .local/public-v1-rerun/qwen3-0.6b
python -m workbench.benchmark_report --runs .local/public-v1-rerun
```

Defaults preserve the recorded protocol: all frozen cases, original followed by reversed options for each case, one excluded warmup per model, 2,000 bootstrap resamples, seed 42, no silent truncation, and explicit failures retained in the denominator. Reruns record their own source hashes, checkpoint metadata and timings; exact numeric equality across hardware or software environments is not promised.
